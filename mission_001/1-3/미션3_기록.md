# 미션 1-3 기록 - 직접 써보고 피드백 주고받기

> 확인 방법: `민수_기획서.md`와 `민수_영화티어리스트.html`의 코드를 읽고 판단했습니다. 브라우저에서 직접 눌러 본 결과는 아닙니다.

## 1. 기획서 완성 기준 확인 (피드백 보기 전)

| 완성 기준 | 결과 | 근거 |
|---|---|---|
| 영화가 한 칸에만 있고, 옮긴 칸에 남는다 | 충족 | `moveTo()`가 `item.tier` 하나만 바꾼다 |
| 제목을 입력하면 새 카드가 생긴다 | 충족 | 제출 시 `미분류`로 추가 |
| 다시 열어도 영화와 등급이 남는다 | **미충족** | `localStorage` 사용 코드가 없다 |
| 화면 폭이 좁아져도 오른쪽이 잘리지 않는다 | **미충족** | `.page { width: 960px }` 고정, `@media` 없음, `body`는 `overflow-x: hidden`이라 잘려도 스크롤이 안 된다 |
| '처음으로'로 처음 8개가 모두 미분류로 돌아간다 | 충족 | `state = fresh()`로 8개만 새로 만든다 |
| 외부 파일·로그인 없이 HTML 한 장으로 열린다 | 충족 | 외부 링크 없음 |
| (기획서에는 없음) 빈 제목 | **미충족** | 검사 없이 `title`이 빈 카드를 추가한다 |

## 2. 받은 피드백을 하나씩 확인

### AI 검토

| 지적 | 직접 확인 | 판단 |
|---|---|---|
| 1. 저장 기능이 없다 | 맞다. `localStorage`가 없다 | 사실 |
| 2. '처음으로'가 직접 추가한 영화를 지우지 않는다 | **틀리다.** `fresh()`가 8편만 담은 새 상태를 만들어 추가한 영화도 사라진다 | AI의 오판 |
| 3. 빈 제목을 막지 않는다 | 맞다. 공백만 넣어도 `trim()` 후 빈 제목 카드가 생긴다 | 사실 |

AI가 말한 세 가지를 모두 믿으면 안 된다. 2번은 코드를 읽어 보니 반대였다.
또 AI는 화면 폭 문제를 짚지 않았다. 동료는 휴대폰에서 불편하다고 했고, 이는 위 표의 '미충족'과 맞는다.

### 동료 피드백

| 의견 | 확인 | 민수 님 입장의 결정 | 이유 |
|---|---|---|---|
| 등급마다 색이 달라 좋다 | 맞다 | 유지 | 장점 |
| 'N편 중 M편 나눔' 표시가 좋다 | 맞다 (`#stat`) | 유지 | 장점 |
| 끌 때 칸 색이 바뀐다 | 맞다 (`is-over`) | 유지 | 장점 |
| 휴대폰에서 불편하다 | 960px 고정 폭 때문 | **반영** | 완성 기준 위반이다 |
| 카드 옮기는 방법이 헷갈린다 | '카드를 고른 뒤 등급을 누르세요'는 선택 직후에만 나온다 | **반영** | 처음 화면에 한 줄 안내를 둔다 |
| 미분류가 아래라 끌어 올리기 불편 | 칸 4개가 156px씩이라 길어진다 | **보류** | 위치를 바꾸면 화면 설계가 바뀐다. 먼저 폭 문제를 고치고 다시 본다 |
| 카드 색이 칙칙하다 | 취향 | **확인 요청** | 어떤 색이 좋은지 물어본다 |
| 포스터 사진을 넣자 | 외부 파일 없이 HTML 한 장이라는 기준과 충돌 | **보류** | 기준을 바꿀지 먼저 정한다 |
| C칸은 없어도 된다 | 기획서가 S·A·B·C로 정함 | **보류** | 기획서를 바꿀 때만 가능 |

## 3. 아무도 말하지 않았지만 내가 찾은 것

- 이미 있는 제목을 또 추가해도 막지 않는다. 같은 제목 카드가 둘 생긴다.
- `badge.innerHTML`과 `#stat`의 `innerHTML`에는 제목이 들어가지 않아 안전하다. 카드는 `textContent`를 써서 안전하다.
- 저장이 없으니 새로고침하면 사용자가 추가한 영화가 모두 사라진다.

## 4. 민수 님이 남길 커밋 메시지 (반영한 의견 하나)

> 화면 폭을 960px 고정에서 최대 960px로 바꾸고 좁은 화면용 규칙을 추가
> 휴대폰에서 오른쪽이 잘려 기획서의 '화면 폭이 좁아져도 잘리지 않는다'를 지키지 못했음.
